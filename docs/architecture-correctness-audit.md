## 已复现的问题

### P1：审查工具可能修改被审查源文件

位置：`src/repo_review_agent/linters.py`，`_run_ruff`。

触发：目标仓库包含 `ruff.toml`，内容为 `fix = true` 和 `[lint] select = ["F401"]`；`app.py` 包含未使用的 `import os`。在临时目录调用真实 `ruff_findings` 后，导入被删除，返回问题数量为 0。

原因：命令未明确禁止修复，读取并接受了目标仓库的自动修复配置。对于本地目标会直接修改用户文件；对于克隆目标会改变正在审查的证据。

验收：不论目标配置是否启用修复，审查前后文件字节一致，仍报告原始违规。公开仓库审查使用受信工具策略，并将工具失败与“无发现”分开表示。

### P1：保存失败仍留下已完成的、不完整历史

位置：`src/repo_review_agent/history.py`，`save_report`、`_insert_review_run`。

触发：使用已有测试的存储替身，在写入 `findings` 时注入故障。此前 `review_runs` 写入已成功，状态为 `completed`，后续明细与 AI 结果未写入。探针仅验证客户端调用顺序，没有连接真实 PostgreSQL。

影响：历史页可能显示不完整结果，后续对比可能把缺失明细误判为问题已解决。保存成功但任务完成写入失败时，恢复重跑还可能重复创建历史。

验收：事务保证运行记录与所有明细一起提交；稳定操作 ID 保证重试不会重复保存；同一仓库并发保存有确定的比较基线；任务租约失效后旧执行者不能提交最终结果。

### P1：数据库明细保存绕过报告脱敏边界

位置：`src/repo_review_agent/history.py`，`_insert_findings`、`_insert_ai_review`；`models.py` 的 `ReviewReport.to_dict`。

触发：构造带合成 `sk-` 密钥的 Finding。`report.to_dict()` 会脱敏，但存储替身捕获的 `findings` 写入仍含原值。没有读取真实密钥，也没有向远端发送探针数据。

影响：接口与数据库使用不同序列化路径，前者脱敏不保证后者安全；摘要、明细、diff、AI 字段和 Markdown 应共用明确的持久化边界。并非声称已发现真实密钥泄漏。

验收：检查完整持久化载荷以及公开错误响应，不包含合成敏感值；不得把对数据库认证头的处理误当成报告脱敏。

### P2：仓库自身策略能隐藏检查结果，原始发现未保留

位置：`service.py` 自动加载 `.repo-review.json`；`config.py` 的 `apply_review_config`。

触发：用测试报告的两个类别配置 `disabled_categories`，发现数从 2 变为 0，输出仅保留抑制数量，没有被抑制记录。

这是当前已支持的自定义行为，但对“审查不受信任的第三方仓库”不构成可靠策略边界。仓库可以关闭或降级针对自身的检查，服务端没有强制策略优先级。

验收：公开审查默认不接受仓库弱化策略；受信本地工作流显式启用；保留脱敏后的原始发现、有效发现、抑制原因与策略来源。原始在此表示未经策略过滤，并非未经脱敏。

### P2：历史接口暴露底层存储错误

位置：`web.py` 的历史列表、详情和反馈接口。

触发：向历史列表接口注入带内部详情的 `HistoryStoreError`，HTTP 400 的 detail 原样包含内部文本。其他任务接口已有安全的 503 映射，但历史接口未统一。

验收：输入错误为 400/422、找不到为 404、存储不可用为安全 503；响应中没有数据库响应正文；日志按统一脱敏规则记录可排查信息。

## 架构观察

- `web.py` 837 行，包含 API、配置、认证缓存、任务调度、两种存储实现及实际审查流程；`history.py` 815 行，混合领域计算和 HTTP 持久化；前端 `main.jsx` 1787 行。
- 静态 AST 检查（包含延迟导入）发现 `job_runtime → web → job_runtime` 与 `models → findings → models` 两个依赖环。它们不等同于已发生导入崩溃，但会妨碍独立运行 worker 和隔离测试。
- worker 为调用业务流程而导入 Web 模块，间接执行模块级应用创建；依赖方向应该反转。
- 配置在模块导入时读取，并与运行期环境读取混用；应用实例的配置与资源隔离难以验证。
- 当前 CI 未验证真实 PostgreSQL 的事务、RLS、迁移顺序、并发租约与失败恢复。

建议采用分层模块化单体，具体边界与验收见 `docs/superpowers/specs/2026-10-06-industrial-architecture-design.md`。本报告不是安全审计认证，也不声称已穷尽所有缺陷。
