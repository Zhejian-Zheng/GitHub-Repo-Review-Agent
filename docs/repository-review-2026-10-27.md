# Repository review: security and failure boundaries

Baseline: `origin/main` at `f1730b3`. Branch: `improve/review-security-runtime`.

## Architecture inspected

- CLI (`cli.main`), HTTP (`web.create_app`), MCP (`mcp_server.create_mcp_server`) and PR bot (`pr_bot.run_pr_bot`) converge on `service.run_review`. Legacy OpenAI/ChatGPT adapters delegate to `RepoReviewAgent` rather than maintaining separate inference loops.
- `ReviewSession` owns the scan, bounded tools, redacted source and previously exposed evidence. `RepoReviewAgent` prepares a deterministic report, then uses LangChain tool calling, Pydantic structured output, call limits and token reservations. `provider.create_chat_model` supplies provider integrations. Direct synthesis cannot add unverified code findings. Report questions use local lexical retrieval over report evidence, not an embedding/vector database or a fresh repository scan.
- HTTP reviews use bounded thread admission around isolated process groups. The supervisor enforces deadlines/cancellation; durable jobs claim fenced leases and commit history/completion together through `save_review_history`. `persistence.history_payload`, canonical findings and coverage certificates preserve identity, feedback and the distinction between resolved and unverified findings.
- Supabase migrations, RLS, service-role grants, atomic operation receipts and question-capacity leases were inspected alongside the integration tests. `schema.sql` is a legacy bootstrap, not the complete current schema. No production database was accessed.
- React review/history/auth hooks, polling and token refresh clients, report/feedback/question views, browser tests, CI/Pages/PR-bot workflows, Dockerfiles, compose and Render configuration were reviewed against the existing architecture, lifecycle, evaluation, deployment and improvement documents under `docs/`.

## Prioritized findings

| Priority | Finding and concrete boundary | Disposition |
| --- | --- | --- |
| P1 | **Credentials follow redirects.** Auth/storage/GitHub requests used urllib's default redirect handler, which can copy `Authorization` and `apikey` to a redirected destination. A redirecting service URL or gateway could expose service credentials. | Fixed: shared credential HTTP opener rejects redirects, including write requests. Real local HTTP tests cover GET/POST with 301/302/303/307/308. Canonical URLs are now required. |
| P1 | **IP throttling trusts caller-controlled headers by default.** `web.enforce_api_access_controls`, `security.client_identifier` and `.env.example` trusted `X-Real-IP`/`X-Forwarded-For` without deployment evidence of a sanitizing proxy. Rotating a header bypassed the limit. | Fixed: default trust is false; explicit trusted-proxy configuration remains supported and tested. ASGI/Uvicorn proxy trust still needs correct deployment configuration. |
| P1 | **Unbounded repository acquisition.** `targets.resolve_target` bounds clone duration, but has no checkout/object/disk quota; `scanner.scan_repository` constructs the complete inventory before applying `max_files`. An oversized repository can exhaust disk or memory within the time budget. | Open: requires deployment resource quotas and a clearly specified inventory/acquisition budget, with partial-coverage semantics. A shallow clone alone does not bound checkout size. |
| P2 | **Auth/storage errors escape the privacy and error boundary.** `auth.get_supabase_user` returned HTTP error bodies/network reasons and assumed an object response. `history._request` leaked transport/decode exceptions past `HistoryStoreError`, bypassing safe 503 mapping and completion retry handling. | Fixed: generic errors, explicit object checks, HTTP/encoding/JSON/connection failure normalization. Tests include safe HTTP 503 for malformed storage data. |
| P2 | **Shared API bearer authentication is broken.** `web.authenticated_user_from_request` verified an API-only bearer credential as a Supabase user token before the API guard ran, contradicting documented API-only use. Non-ASCII token comparisons also raised `TypeError`. | Fixed: distinguish API credential from user identity, compare encoded bytes. Required-login/history/question routes still require a user JWT; the shared API credential cannot impersonate a user. |
| P2 | **Malformed workers can publish invalid success; recovery can publish input.** `job_runtime.run_isolated` trusted any parsed envelope, even after nonzero exit. `SupabaseBackedReviewJobStore.sweep` persisted Pydantic exception strings containing the original invalid request values. | Fixed: require successful process exit and a single typed result/error outcome; recovered-start failures use a generic message. Existing deadline/cancellation cleanup remains intact. |
| P2 | **Request/resource limits apply after parsing.** FastAPI parses request JSON before the 200 KB report check in `web.report_question`; auth/history response reads and worker output reads also have no byte cap. `run_isolated.watch_cancellation` can outlive its one-second join if storage blocks. | Open: enforce ingress byte limits and bounded transport/output readers with sizes that preserve valid large reports; consider one bounded cancellation polling service rather than accumulating blocked monitors. Socket timeouts alone are not complete resource budgets. |
| P2 | **Frontend review state lacks the history hook's identity guards.** `useReviewJob.runReview` refreshes the session before its try/finally and writes status/loading state without checking the current controller in every continuation. A refresh rejection or old run settling after reset/new submission can leave stale UI state. | Open: move the complete lifecycle into guarded try/finally and add delayed-session/run browser regressions. Existing cancellation-response guards do not cover every continuation. |
| P2 | **Review accuracy remains a separate gate.** `ReviewSession.validate_findings` verifies quotation/location, not whether a diagnosis is true. `questions._select_evidence` is lexical and caps retrieved evidence; `analyzer.analyze_snapshot` retains global conservative content coverage. | Open: grow human-adjudicated semantic evaluations, cross-file context and per-rule coverage. Offline precision on hygiene fixtures cannot establish live model defect precision. |
| P2 | **PR bot installs floating dependencies and can post stale results.** `.github/workflows/repo-review-bot.yml` used unlocked editable pip installs and lacked per-PR concurrency. Older runs could finish after newer heads and overwrite the sticky comment. | Fixed: pinned uv with locked core install from the trusted base checkout; cancel superseded runs by PR/ref. Cancellation reduces overlap; it is not an atomic GitHub head check at publish time. |
| P2 | **Deployment instructions can create a nonfunctional or falsely private demo.** `docs/demo-runbook.md` omitted required migrations and advertised a Vite-bundled shared token as private. `docs/deployment.md` described duplicate history behavior predating atomic completion. | Fixed: complete migration chain, browser-token visibility explanation, current persistence and proxy policy. Existing bundled credentials, if any, are not rotated by code changes. |
| P3 | **Composition and schema maintenance still drift.** `web.py` creates a module-level app and globals in addition to factory-created apps; job code calls storage `_request` directly. The legacy schema, verification SQL, migration chain and numerous dated docs require coordinated updates. | Open: incremental composition/config isolation and storage ports, plus a generated/current schema snapshot. Avoid a broad package rearrangement in a security fix. |

## Validation and limitations

Regression tests first reproduced the affected baseline behavior, including auth body exposure, forged IP identities, malformed worker outcomes, invalid recovered input and API bearer misclassification. New tests use synthetic credentials and local HTTP only. The full suite also exercises real framework tool calling with fake models, canonical report round trips and process cleanup.

Final verification:

- `uv sync --locked --all-extras --python 3.10` and `--python 3.12` with isolated `UV_PROJECT_ENVIRONMENT` directories: passed.
- `coverage run -m unittest discover -s tests` followed by `coverage report` in both locked environments: **526 tests each, 525 passed and one opt-in live-model test skipped; 97% coverage**, above the unchanged 95% gate.
- `python scripts/test_postgres.py`: **17 passed**, using a temporary PostgreSQL 16 cluster; migrations, transactions, RLS, concurrency and leases included.
- `npm test`: **12 passed**. `npm run build`: passed.
- `PLAYWRIGHT_CHANNEL=chrome npm run test:browser`: **15 passed**. The default browser invocation could not launch because the Playwright-managed Chromium executable was absent; the installed Chrome channel completed the suite.
- `python -m repo_review_agent.evaluation tests/fixtures/evaluation/dataset.json --min-precision 1 --output /tmp/repo-review-evaluation.json`: passed, offline fixture precision/recall 1.0.
- `ruff check src tests`, `python -m compileall -q src tests`, `uv lock --check`, `git diff --check`: passed. PR-bot YAML and both locked installation steps parsed/validated; a core-only locked install ran the real CLI against the healthy fixture.

 No paid model, production Supabase/OAuth, live GitHub review-comment/check publishing or production deployment was exercised. Docker cannot be built locally because no Docker executable is installed; image build remains in CI.

No database migration or destructive data change is required by this PR. Redirecting credential endpoints must be configured directly; deployments enabling forwarded-header trust must sanitize those headers. These intentional changes fail closed and may require configuration updates.
